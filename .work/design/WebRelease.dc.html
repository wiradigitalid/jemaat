What this decision does not touch
Worth stating, because a surface change invites a redesign nobody asked for.
S5, the data model. Not one table moves. A surface is not a schema.
S6, the palette and type. Built with no shadows and web-safe fallbacks from the start, which is why these artboards needed no restyling.
S7, the channel. WhatsApp for anything you must act on, and it now carries sign-in too.
W1–W17. Already web. Already responsive at the two widths that matter.
S2 and S3. The warta and the noticing decisions are still yours, and still unanswered.
Deferred, not cancelled
Every phone artboard in this canvas stays valid: 390 is a phone browser as readily as an app frame, and each one is now a route against the same API. A native shell later re-skins routes that already work rather than reopening a design.

The one thing to keep honest: R0 W is not a smaller R0. It is the same product on one surface, and the app becomes a distribution decision instead of a build.
3 Before anyone builds
None of these is a design question, and all three decide a schedule.
The offline queue is a spike, not a story. Ticks must survive a killed tab and a dead connection, and land exactly once when they send. Prove it on a real cheap Android in a real hall before B3 is called done.
The church URL is not the church name. It. 37 refused a browsable index of congregations; a guessable path reopens it. The code is the path, and a name path is opt-in per W4.
Sign-in links need approved templates. Same vendor queue as every other act-now message, and the same reason not to discover it in month two.
Still open, and still not mine
No DEC- has been written for anything, and this decision is now the largest of them. Start already names the gap; web first makes it structural rather than tidy.
Time zones are named on W12 and applied nowhere. Every screen still says 19.30 and none says which.
The pilot church has not seen any of this. Everything here is a claim until a leader marks one Wednesday in a hall.
